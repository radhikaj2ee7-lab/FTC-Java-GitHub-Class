## 📁 Repository Structure

Please follow the folder naming convention below to keep our repository organized.

```text
FTC-Java-Learning/
│
├── README.md
│
├── StudentName/
│   ├── JavaBasics/
│   ├── GitHubPractice/
│   └── FTCProgramming/
│
└── SharedResources/
```

### Folder Naming Rules

1. Create a personal folder using your name.
2. Use your name without spaces. For example, `AlexSmith`, `PriyaPatel`, or `JohnDoe`.
3. Keep your practice files inside your personal folder.
4. Use clear, meaningful names for subfolders and files.
5. Do not modify another student's folder unless the instructor asks you to do so.

**Example:**

`john/JavaBasics/HelloWorld.java`

## 🌿 Step 1: Create Your Own Branch

A branch lets you work on your code independently without directly changing the main branch.

**Follow these steps:**

1. Open this repository on GitHub.
2. Click the branch dropdown near the top-left of the repository.
3. Type your new branch name.
4. Select **Create branch**.

### Branch Naming Convention

Use the following format:

`studentname-practice`

**Examples:**
- `john-practice`


Use lowercase letters and avoid spaces.

**Remember:** Do your work on your own branch. Do not commit your practice changes directly to `main`.
Create a Pull Request(PR) from your branch to main for the instructor to review and merge the PR

---

## 💻 Step 2: Organize Your Code

Once you have created your branch:

1. Create a folder using your name if it doesn't already exist.
2. Create the appropriate subfolder for your exercise.
3. Add your Java files or other practice materials.
4. Save your changes.

**Example:**

```text
PriyaPatel/
└── JavaBasics/
    ├── HelloWorld.java
    ├── VariablesDemo.java
    └── LoopsPractice.java
```

Keep your code organized so you and your teammates can easily understand it.

---

## ✅ Step 3: Commit Your Changes

A **commit** is a snapshot of your changes. Every commit should have a clear message explaining what you changed.

### Commit Message Format

Use this format for every commit:

`YourName - Description of your change`

**Examples:**

- `John - Added HelloWorld Java program`

### Commit Guidelines

- Always begin your commit message with your name.
- Add a hyphen (`-`) after your name.
- Briefly describe what you changed.
- Keep the message simple and meaningful.
- Make small, focused commits instead of combining unrelated changes.

**Good commit:** `John - Added Java if-else examples`

**Avoid:** `Changes`, `Update`, `Test`, or `Done`

---

## 📤 Step 4: Push Your Changes to GitHub

After committing your changes, push your branch to GitHub so your work is saved and available for review.

If you are using the GitHub website, your edits may be committed directly to your selected branch.

If you are using Git from your computer, the basic commands are:

```bash
git add .
git commit -m "John - Added Java practice examples"
git push -u origin alexsmith-practice
```

Replace the example name and branch with your own.

---

## 🔍 Step 5: Review and Share Your Work

When you finish an exercise:

1. Check that your files are in the correct folder.
2. Verify that your commit message follows the naming convention.
3. Push your changes to GitHub.
4. Share your branch with the instructor for review.
5. Make improvements based on feedback.

The instructor will guide you on when and how to merge approved work into the `main` branch.

## ⭐ Our Team Guidelines

To make learning enjoyable and teamwork successful, please follow these guidelines:

- **Learn by doing:** Try writing the code yourself before looking at a solution.
- **Ask questions:** No question is too small.
- **Make mistakes:** Errors are part of learning and debugging.
- **Respect everyone's work:** Keep your changes in your own folder.
- **Write readable code:** Use meaningful variable names and proper indentation.
- **Collaborate:** Help teammates understand concepts rather than simply giving them answers.
- **Keep GitHub organized:** Follow the folder, branch, and commit naming conventions.
